## 2. 组件与端口

| 组件 | 端口 | 角色 | 启动器 |
|------|------|------|--------|
| grok2api | 8000 | 号池网关：管理台 + OpenAI/Anthropic 兼容 API | `~/bin/grok2api-up.sh` |
| grok-cli-shim | 8802 | grok CLI → grok2api 转换层（换 key 后透传） | `~/bin/grok-shim-up.sh` |
| grok-8800-alias | 8800 | 旧地址转发到 8000 + 浏览器零输入自动登录 | `~/bin/grok-8800-up.sh` |
| grok_oauth | 8799 | 设备码 OAuth：注册链拿 Build token | `~/bin/grok-oauth-up.sh` |
| AutoJs6 服务端 | 7347 | AutoJs6 App 的「服务端模式」，Termux 经它下发脚本 | AutoJs6 侧边抽屉 |
| 收验证码守望 | —— | 挂 QQ 垃圾箱取验证码写文件（tmux 常驻） | `~/bin/start-watch.sh` |

全部只监听 `127.0.0.1`。

## 3. 数据流：从注册到调用

```
① 注册（AutoJs6 WebView）
   x.ai 注册 → 邮箱验证码（守望取回） → 账号密码 + SSO + Build token
   落盘：
     grok_accounts.txt        邮箱----密码
     sso_from_autojs.txt      邮箱----sso
     Download/QQ/grok api/xai-<邮箱>.json （OAuth token）

② 导入（g2a_*.py 工具）
   Build 池  ◄── g2a_import_new.py     （token 文件）
   Web 池    ◄── g2a_web_test.py       （sso + 预处理）
   Console 池◄── g2a_sync_console.py   （从 Web 号同步）

③ 服务（grok2api）
   多池调度：轮换、额度优先、失败熔断、质量守护（可选）
   对外一个 base_url + 一个 g2a_ key

④ 调用
   Hermes / OpenAI SDK / grok CLI / 自己的程序 → 127.0.0.1:8000（或 8802 / 8800）
```

## 4. 三个池的区别

| 池 | 上游 | 强项 | 注意 |
|----|------|------|------|
| Build | cli-chat-proxy（OAuth） | 文本、Agent 工具调用 | 模型 grok-4.5/4.6/4.7/composer… |
| Web | grok.com（SSO） | 图像、视频 720p、chat-fast | 出图/视频主力 |
| Console | console.x.ai（SSO 同步） | 视频、TTS/STT/Realtime | chat 10 条/号/天 |

裸模型名默认走 Console；要指定池用前缀：`Build/grok-4.5`、`Console/...`、`Web/...`。
